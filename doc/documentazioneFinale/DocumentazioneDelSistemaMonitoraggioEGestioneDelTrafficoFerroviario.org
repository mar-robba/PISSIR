* Introduzione Descrizione Generale
Cio che è realizzato è al fine della gestione di una rete ferroviaria e, in particolare, la gestione
delle stazioni, dei treni che compongono tale rete.
La gestione della rete è fornita attraverso in un app web che fornisce il neccessarrio per il monitoraggio e l'amiinistrazione della rete

** Elenco informale dei requisiti  funzionali
*** funzionalita da espletare per ogni componente
**** microservizio treno
- aggiornamento tratta
  - salvarla in ram per il proprio uso e sul db
- gestione causa guasti alla prossima fermata stazione o binario (tratatta ovvero copia di stazioeni)
  - ricezione dai sesori --> modifica della percorrenza della tratta, sincronizzazione sui topic di allarme delle
    nuove stazioni
    - se arrivano evendi del tipo la prossima stazione è fuori uso aggiornare variabile in rame e il database
      che il treno si è femato e
    - se l'evento è il ripristino della funzionalità della stazione allora riaggiornare la ram e il db che il
      treno è partito
- Ritardi la tratta possiede orari corretti di percorrenza
- inviare in certrale l'entrata e uscita da una stazione topic treni/+/passaggio
  formato : boh lo fa l'ai
- invio se il treno si guasta alla centrale
**** microservizio stazione
- invio alla centrale i dati del passaggio dei treni
  - i sensori della stazione informano id treno e se è in entrata o in uscita,
    poi si aggiorna la ram e si inviano i dati alla stazione centrale per la storicizzazione
- la staione può perdere la connessione
     con la centrale nel caso seguire il diagramma degli stati che ne
    descrive la dinamica di gestione
**** Centrale
 - deve rispondere alle richieste di visualizzazione
   - montare su il motore in tepo reale, cicli continui che inviano i dati se la richiesta è ancora attiva
 - formattare e storicizzare i dati
 L'unica crud a cui serve la propagazinone ai microservizzi è la
 - gestione guasti
   - se i microservizzi avvertono guasti , aggiornamento del db,
   - se il tecnico invia l'operatore aggiornare il db di modo che ormai il guasto sia terminato e
     pubblicare sul topic degli allert generale per tutti i treni o tutte le stazioni che quel tale microservizio è stato risolto
 interrogare il database ogni 10 secondi per ogni tipo di visualizzazione di modo da rendere il "tempo reale"

state "Motore di Viaggio – Digital Twin\n(TrainJourneyEngine)" as MotoreDiViaggio {

    ' --- Caricamento itinerario ---
    state "Attesa Itinerario" as AttesaItinerario
    note left of AttesaItinerario
      GET /api/treni/{id}/itinerario
      verso la Centrale Operativa.
      Retry ogni 15s se fallisce.
    end note

    state "Itinerario Caricato\n(>= 2 stazioni)" as ItinerarioCaricato

    state "Avvio Viaggio\n(avviaViaggio())" as AvvioViaggio
    note right of AvvioViaggio
      Posiziona il treno alla prima
      stazione, stato = FERMO,
      faseViaggio = IN_STAZIONE,
      genera passeggeri iniziali.
    end note

    ' --- Ciclo di simulazione (macchina a stati) ---
    state "Ciclo di Simulazione\n(tick ogni 1s)" as CicloSimulazione {

        state "IN_STAZIONE\n(FERMO)" as InStazione
        note bottom of InStazione
          Attende scadenza sosta.
          Non parte se stazione
          corrente/prossima guasta.
          Sosta doppia al capolinea.
        end note

        state "IN_VIAGGIO" as InViaggio
        note bottom of InViaggio
          Interpola GPS tra le due
          stazioni, avanza il
          progressPercent con il
          tempo scalato dal fattore
          di accelerazione.
        end note

        state "BLOCCATO\nGUASTO STAZIONE" as Bloccato
        note bottom of Bloccato
          Treno fermo, accumula
          ritardo. Congela il
          progressPercent se
          bloccato a metà tratta.
        end note

        state "EMERGENZA\n(guasto di bordo)" as Emergenza
        note bottom of Emergenza
          Guasto rilevato dai sensori.
          Viaggio congelato: il tempo
          di tratta non avanza.
          Velocità = 0.
        end note

        state "SOPPRESSO" as Soppresso
        note bottom of Soppresso
          Stato definitivo.
          Corsa cancellata dalla
          Centrale (alert STOP).
          faseViaggio = TERMINATO.
        end note

        state "Inversione al\nCapolinea" as Inversione

        ' --- Transizioni principali ---
        [*] --> InStazione

        InStazione --> InViaggio : sosta scaduta\n+ stato = FERMO\n+ nessuna stazione guasta\n[pubblica USCITA MQTT]
        InViaggio --> InStazione : progressPercent >= 100%\n(arrivo in stazione)\n[pubblica ENTRATA MQTT]

        ' --- Inversione ---
        InStazione --> Inversione : arrivo al capolinea\n(ultimo/primo indice)
        Inversione --> InStazione : direzione invertita\n(andata <-> ritorno)\nsosta doppia

        ' --- Guasto stazione ---
        InStazione --> Bloccato : alert GUASTO CRITICAL\nstazione corrente/prossima
        InViaggio --> Bloccato : alert GUASTO CRITICAL\nstazione corrente/prossima
        Bloccato --> InStazione : alert RESOLVED\n(ero IN_STAZIONE)
        Bloccato --> InViaggio : alert RESOLVED\n(ero IN_VIAGGIO)

        ' --- Emergenza di bordo ---
        InStazione --> Emergenza : sensore rileva guasto\n[inviaGuasto() MQTT]
        InViaggio --> Emergenza : sensore rileva guasto\n[inviaGuasto() MQTT]
        Emergenza --> InStazione : alert RESOLVED\nper questo TRENO\n(stato -> FERMO)
        Emergenza --> InViaggio : alert RESOLVED\nper questo TRENO\n(stato -> FERMO,\nriprende la marcia)

        ' --- Soppressione ---
        InStazione --> Soppresso : alert STOP target = trenoId
        InViaggio --> Soppresso : alert STOP target = trenoId
        Bloccato --> Soppresso : alert STOP target = trenoId
        Emergenza --> Soppresso : alert STOP target = trenoId
        Soppresso --> [*] : TERMINATO\n(il tick non fa piu' nulla)
    }

    ' --- Transizioni esterne al ciclo ---
    [*] --> AttesaItinerario
    AttesaItinerario --> AttesaItinerario : Centrale irraggiungibile /\nHTTP != 200 /\n< 2 stazioni\n(retry ogni 15s)
    AttesaItinerario --> ItinerarioCaricato : HTTP 200 +\nparsing JSON OK
    ItinerarioCaricato --> AvvioViaggio : autostart = true
    AvvioViaggio --> CicloSimulazione

    ' --- Ricarica itinerario ---
    CicloSimulazione --> AttesaItinerario : alert ITINERARIO_AGGIORNATO\n(reset completo,\nricarica dalla Centrale)
}

@enduml
